# Documentation & consistency audit — 2026-08-12

Register of every finding from the 2026-08-12 audit. Five independent read-only
passes verified each documented claim against the source at
`d6118b9c` (server v1.9.6, firmware 1.3.4), plus findings from hands-on
debugging of two field bugs on the same day.

**How to read this.** Every entry names the claim, the ground truth with a
`file:line` citation, and a status. Nothing here is speculative: a finding was
only recorded after the ground truth was read in the source. Where a later fix
landed, the PR is named — those entries are kept rather than deleted, because the
*reason* is the durable part.

| Status | Meaning |
|--------|---------|
| ✅ fixed | Corrected; PR named |
| 🔧 open | Confirmed defect, not yet addressed |
| ⛔ blocked | Needs information we do not have (hardware datasheet, schematic) |
| 📋 noted | Accurate but worth knowing; no action implied |

Severity is about consequence, not effort: **CRITICAL** = following the doc
breaks something or hides an exposure; **MODERATE** = misleading, costs time;
**MINOR** = cosmetic or stale wording.

## 1. Headline: the audit inverted its own premise

The task assumed `CLAUDE.md` was the trustworthy handoff doc and the other docs
were stale. The opposite held. Every doc that the previous `CLAUDE.md` listed as
stale had since been fixed, while `CLAUDE.md` itself had drifted into being the
most dangerous file in the repo — it is the file every fresh AI session reads
first, and it recommended a release recovery procedure that now corrupts
release-please state.

Corrected in `4ce00428` and `8be40161`.
